EMY Cloud Edition V2 — التشفير ومفتاح الاستعادة والنسخ الاحتياطي

1) هذه النسخة تستخدم Supabase لتسجيل الدخول بالبريد الإلكتروني وكلمة المرور.
2) تُشفّر بيانات كل مجموعة داخل المتصفح باستخدام AES-GCM قبل إرسالها إلى Supabase. مفتاح البيانات عشوائي مستقل عن كلمة مرور الحساب.
3) يُغلّف مفتاح البيانات بطريقتين منفصلتين: كلمة مرور الحساب، ومفتاح استعادة عشوائي يُعرض مرة واحدة عند إعداد التشفير.
4) عند أول دخول لحساب جديد، أو عند ترحيل بيانات النسخة القديمة، يجب تنزيل مفتاح الاستعادة وحفظه خارج الجهاز في مكان آمن قبل متابعة فتح التطبيق. من يفقد كلمة المرور ومفتاح الاستعادة معًا لا يمكنه فك البيانات.
5) عند نسيان كلمة المرور: اضغطي «نسيت كلمة المرور؟»، افتحي رابط Supabase من البريد في المتصفح نفسه، ثم أدخلي مفتاح الاستعادة وكلمة مرور جديدة. يجب إضافة رابط الموقع المنشور إلى Supabase > Authentication > URL Configuration > Redirect URLs.
6) من شريط الحساب يمكن تنزيل نسخة احتياطية مشفّرة بصيغة JSON واستيرادها للحساب نفسه. ملف النسخة يحتوي بيانات مشفّرة ومعلومات وصفية، ولا يُعد نسخة قابلة للقراءة دون كلمة المرور أو مفتاح الاستعادة.
7) زر «تجديد مفتاح الاستعادة» يلغي صلاحية المفتاح السابق بعد حفظ المفتاح الجديد وتحديث السجلات السحابية. احفظي المفتاح الجديد فور ظهوره.
8) يمكن ترحيل بيانات V1 المشفّرة إلى V2 فقط عند تسجيل الدخول بكلمة المرور الأصلية التي شُفّرت بها. إذا كانت كلمة المرور الأصلية مفقودة، فلا يمكن تحويل V1 إلى نظام الاستعادة بأثر رجعي.
9) البيانات القديمة غير المشفّرة في Supabase لا تصبح مشفّرة بمجرد رفع الملفات الجديدة؛ يجب تسجيل الدخول بالنسخة V2 حتى تتم عملية الترحيل. احتفظي بنسخة احتياطية قبل ذلك.
10) localStorage في المتصفح يحتوي البيانات بصورتها المقروءة أثناء الجلسة. هذا التشفير يحمي محتوى قاعدة Supabase من القراءة المباشرة، ولا يحمي جهازًا مفتوحًا أو متصفحًا مخترقًا.
11) حقول مثل user_id وcollection وrecord_id ووقت التحديث والبريد الإلكتروني تبقى ظاهرة في خدمات Supabase. محتوى data هو الذي يُشفّر.
12) لا تستخدمي بيانات طالبات حقيقية قبل اختبار التسجيل والدخول والمزامنة والاستعادة والنسخ الاحتياطي بحسابات وبيانات وهمية، والحصول على موافقة المعلمة/المدرسة عند الحاجة.

التشغيل:
- لا تفتحي index.html مباشرة عبر file://.
- شغّلي المشروع عبر Live Server أو استضافة HTTPS مثل Cloudflare Pages.
- في Supabase > Authentication > URL Configuration أضيفي عنوان الموقع المنشور إلى Site URL وRedirect URLs. للاختبار المحلي أضيفي عنوان Live Server الصحيح.
- في Authentication > Sign In / Providers اتركي Email مفعّلًا وAllow new users to sign up مفعّلًا إذا كنتِ تريدين إنشاء حسابات جديدة.
- لا تضعي service_role أو أي Secret Key في ملفات المتصفح. المفتاح الموجود في auth.js هو Publishable Key فقط.

مهم: هذه نسخة اختبارية تحتاج اختبارًا عمليًا في المتصفح وعلى Cloudflare قبل اعتمادها. افحصي سجل Supabase للتأكد من أن data يحتوي __emyEncrypted: true وversion: 2 وciphertext، ولا يحتوي أسماء الطالبات أو العلامات كنص واضح.
